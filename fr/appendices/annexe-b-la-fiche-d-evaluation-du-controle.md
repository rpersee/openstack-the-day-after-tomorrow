# Annexe B — La fiche d’évaluation du contrôle

Pour chaque capacité OpenStack critique, consigner les preuves pour chaque question. Si la réponse est « nous pensons que oui », le niveau de contrôle n’est pas encore établi.

| Question | Preuves |
| ------------------------ | ---------------- |
| Quelle capacité métier en dépend ? | |
| Quels services OpenStack y participent ? | |
| Quelles dépendances externes y participent ? | |
| Qui est propriétaire de la capacité ? | |
| Qui l’exploite ? | |
| Qui peut la diagnostiquer ? | |
| Qui peut la rétablir ? | |
| La reprise est-elle démontrée ? Quand, par qui ? | |
| Quels signaux indiquent une dégradation ? | |
| Quels changements l’affectent couramment ? | |
| Quelles personnalisations l’affectent ? | |
| Quelle divergence upstream existe ? | |
| Quelle dépendance à un expert unique existe ? | |
| Quel est le niveau de contrôle actuel (Inconnu → Durable, critères au chapitre 5) ? | |
| Quelle est la lacune de contrôle la plus importante ? | |
| Que faut-il faire maintenant ? | |
| Qu’est-ce qui peut attendre, et jusqu’à quand ? | |
